# 公開後の共有・ホーム画面追加

## 反映手順

1. Supabase SQL Editorで `scripts/add-app-appearance.sql` を実行する。追加テーブルのみ。既存アプリ・保存データは変更しない。
2. 通常のデプロイを行う。
3. 日本語と英語で、保存あり・保存なし・グループ共有のアプリを公開し、公開後の案内を確認する。
4. 所有者とゲストの公開端末でアイコン保存を確認する。他のアカウントからの変更は403になる。
5. iPhone / Android実機でホーム画面追加と起動先を確認する。既存インストールのアイコン変更反映はOS次第のため、再追加が必要な場合がある。

## 計測

`analytics_events` の `engagement` イベントを使用。専用テーブル追加は不要。propsにはアプリID・ランダムなブラウザID・行動・共有先・共有IDを記録する。招待トークン、送信相手、メッセージ本文は記録しない。

共有先は専用ボタンの選択先。実送信は判定不可。標準共有はnativeとして記録し、選択したアプリは取得しない。ホーム追加完了はappinstalled対応環境のみ。standalone起動は別指標。URLのlaunch=homeだけでは追加成功とみなさない。

管理画面はアプリ×ブラウザを重複排除。案内を見た集合を分母にした操作率と、ホーム画面起動確認率を表示する。共有ID付きリンク訪問は本人による確認も含み、開封率とは呼ばない。再利用は作者以外の異なる日本時間の日付で数える。

## 検証

`node scripts/test-engagement.cjs`

`npx tsc --noEmit --incremental false`

`npm run build`

## 制約

50種類は既存Lucide SVGを用いた統一線画。画像生成の参考案の塗りつぶし・立体表現そのものではない。5色は合意した単色を使用。プレビューとPNGは同じ描画を利用。

オフライン動作・プッシュ通知は含まない。保存方式の判定はコードのAPI利用からの推定。ゲームの結果共有は生成アプリ内の個別対応が必要。7日・30日継続率のコホート集計は別途追加する。
