# ジサップ公式コラムの書き方（AI 向け）

管理画面（/admin/columns）の「AIに頼む」でコピーした依頼文から、このファイルを読んで書いてもらう。
リポジトリ全体を読める AI（ChatGPT・Claude のプロジェクトなど）に頼む前提。

## 事実の確かめ方

- ジサップの機能は、**このリポジトリのコードで確かめてから書く**。コードにないこと・予定のことは書かない
  - 例：データの保存（`window.Jisapp.saveData` / `loadData`）、グループ共有（`window.Jisapp.shared`）、Google ドライブの写真（`window.Jisapp.drive`）、公開・ホーム画面に追加など
  - アプリに頼むときの決まりは `lib/agent/prompts.ts`・`lib/playground/prompt-template.ts`、サービスの説明は `lib/seo/llmo.ts` と `lib/seo/site.ts` にある
- 料金・制限（無料・容量など）は、コードと `app/[locale]/terms` に書いてあることだけ
- 確かめられない数字（「3秒で完成」「1万人が使っている」など）は書かない
- ほかのサービスの悪口は書かない
- 例に出す人の名前・金額は架空にする（そう分かるように書く）

## 読む人と文体

- アプリを作ったことがない人。専門用語（API・デプロイ・データベースなど）は使わないか、言いかえる
- note のような、語りかける文体。です・ます調
- 1文目は「その人に起きた場面」から始める（例：旅行の精算、毎回だれかが電卓をたたいている。）。説明や答えから始めない
- 1つの段落は2〜3文。2,000字くらい

## 構成

1. 場面（誰の、どんな用事で、何が起きているか。数字を入れる）
2. 困っていること（箇条書きで3つまで）
3. アプリにすると、どう楽になるか（いちばんの得を1つ、数字で）
4. AI に送る一文（そのまま使える例を、引用「> 」で）。アプリを作ったときの長いプロンプトがあれば、アプリのカード（`::app[ID]`）のすぐ下に `:::prompt このアプリのプロンプト` 〜 `:::` で入れる
5. ジサップに貼って公開する流れ（グループで使うなら、グループ共有にも触れる）
6. まとめ
7. 最後の行に `::button[ジサップでアプリを作る](/playground)`

## 本文の書き方（この記号だけが記事の形になる。HTML は使えない）

| 書き方 | 記事での見た目 |
|---|---|
| `# タイトル`（1行目だけ） | タイトル欄に入る |
| `## 見出し` / `### 小見出し` | 見出し |
| `**文字**` | 太字 |
| `- 項目` / `1. 項目` | 箇条書き / 番号つき |
| `> 文` | 引用（AI に送る一文など） |
| `[文字](https://…)` / `[文字](/playground)` | リンク |
| `---` | 区切り |
| `::app[アプリのID]` | ジサップのアプリのカード（ID は /apps/<ID> の部分） |
| `::youtube[動画のURL]` | YouTube の動画 |
| `::button[文字](/playground)` | ボタン |
| `:::prompt 見出し` 〜 `:::` | 折りたたみのプロンプト。開くと全文とコピーボタンが出る（中は書いたとおりにそのまま出る） |
| `:::fold 見出し` 〜 `:::` | 折りたたみ（長い補足など。中は本文と同じ書き方） |

画像は書かない（管理画面であとから入れる）。

## 返事の形

- 記事の本文だけを返す。前置き・あとがき・「いかがでしたか」は書かない
- 1行目は `# タイトル`（32文字くらいまで。場面か得が伝わるもの）
- 最後に、本文とは別に次の2つを書く（管理画面の公開設定に貼る）
  - `説明：` 検索結果に出る説明（100文字くらい）
  - `Xの投稿文：` X に投稿する文（120文字くらい。リンクは自動でつくので書かない）
